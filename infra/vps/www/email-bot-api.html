Зачем оно

BMChat — это форк Delta Chat: чат поверх IMAP/SMTP без центральных серверов. Бот не отдельный «account» где-то в облаке, а виртуальный участник на стороне владельца почтового ящика. Бот живёт ровно до тех пор, пока работает почтовый аккаунт владельца — удалили аккаунт → бот замолкает, аналог отключения webhook у Telegram-бота.

Реализация поверх e-mail даёт три эффекта, которых нет у Telegram Bot API:

  • любой почтовый сервер — это полноценный bot-runtime, не нужен публичный HTTPS-endpoint;
  • каждый IMAP-клиент (Thunderbird, mutt, MS Outlook) — это годный backend для бота;
  • история переписки бота физически хранится у самого разработчика — ничего не уходит на сторонний сервер.

Создание бота

  1. BMChat → Настройки → Дополнительно → Email-боты → +.
  2. Заполняете name (с суффиксом bot), display_name, description, developer_email. Аватарку, при желании, можно добавить позже (раздел в разработке).
  3. BMChat генерирует token, кладёт его на экран редактирования — копируете в свой бэкенд.
  4. Включаете переключатель «Бот включён». Готово — бот живой.
Бот не имеет собственного отдельного e-mail. Он отвечает в чатах от имени владельца BMChat с префиксом @botname:, что повторяет поведение Telegram-ботов в групповых чатах.

Команда /start и подписка

Как у Telegram-ботов, BMChat-бот не реагирует на людей, которые не нажали /start. Это защищает разработчика от мусора и повторяет привычный сценарий.

  1. Пользователь в чате с владельцем пишет @helper_bot /start (или /start, если у владельца ровно один бот).
  2. BMChat добавляет e-mail отправителя в subscribed_users бота.
  3. Отвечает приветствием — либо вашим шаблоном из таблицы commands["start"], либо автоматически сгенерированным из display_name + description + список команд.
  4. С этого момента любое сообщение этого e-mail в адрес бота попадает в ваш почтовый webhook.

До /start бот молча игнорирует все обращения — никакого «не понял команду», ровно как у Telegram.

Формат писем (wire format)

Все письма bot-протокола имеют опознавательный маркер в первой строке тела. Delta-chat (на котором стоит BMChat) автоматически берёт первую строку как Subject, поэтому маркер виден ещё до загрузки тела — удобно для серверных фильтров.

1. BMChat → разработчик (update)

From: alice@example.com           ← владелец бота
To:   developer@example.com       ← поле "developer_email"
Subject: BMCHAT-BOT-UPDATE v1 @helper_bot chat=42 message=1715812345 from=bob@example.com

BMCHAT-BOT-UPDATE v1 @helper_bot chat=42 message=1715812345 from=bob@example.com
---
{
  "update_id": 1715812345,
  "message": {
    "message_id": 1715812345,
    "chat": { "id": 42, "type": "private" },
    "from": { "email": "bob@example.com" },
    "text": "/forecast Москва",
    "date": 1715812345
  },
  "bmchat": {
    "bot": "helper_bot",
    "token_suffix": "<первые 16 символов token>",
    "command": "forecast",
    "argument": "Москва",
    "reply_to": "alice@example.com"
  }
}

2. Разработчик → BMChat (reply)

From: developer@example.com
To:   alice@example.com           ← поле "reply_to" из update
Subject: BMCHAT-BOT-REPLY v1 @helper_bot chat=42 in_reply_to=1715812345

BMCHAT-BOT-REPLY v1 @helper_bot chat=42 in_reply_to=1715812345
---
{
  "text": "Москва: +7°C, облачно",
  "parse_mode": "Markdown",
  "reply_markup": {
    "inline_keyboard": [
      [{ "text": "Обновить", "callback_data": "refresh:moscow" }],
      [{ "text": "Открыть прогноз", "url": "https://weather.example.com/moscow" }]
    ]
  }
}
Маркер обязателен и в Subject, и в первой строке тела. Если ваш почтовый клиент дописал Re: — это нормально, BMChat ищет маркер по подстроке.

Update — что приходит разработчику

Top-level и message — повторяют схему Telegram Update; неподдерживаемые поля (entities, photo, voice…) пока не включены.

  • update_id — целое, монотонно растёт (равно message_id во входящем письме).
  • message.chat.id — ID чата на стороне владельца, нужен для маршрутизации reply.
  • message.from.email — обычный e-mail пользователя. BMChat не выдаёт first_name/last_name — у нас единственный идентификатор это e-mail.
  • message.text — полный текст сообщения, как он пришёл. Команда уже выкушена в bmchat.command, но текст лежит в исходном виде.
  • bmchat.token_suffix — первые 16 символов вашего токена. Сверьте с тем, что хранится у вас, чтобы убедиться, что сообщение реально пришло из BMChat.

Ответ — что разработчик отправляет назад

ПолеОписание
textТело ответа. Поддерживается Markdown подмножество BMChat (*жирный*, _курсив_, ~зачёркнутый~, ссылки [label](url)).
parse_modeПодсказка для логирования. BMChat всегда применяет свой Markdown.

replyУстаревший alias для text из BMChat 2.49.47. Если оба заданы — победит text.

Inline-клавиатуры и callback

BMChat рендерит inline-кнопки как Markdown-ссылки на pseudo-схему bmchat-bot://cb/<bot>/<callback_data>. Тап по такой ссылке открывает EmailBotCallbackActivity, которая:

  1. отправляет вам обратное письмо BMCHAT-BOT-UPDATE v1 … command=callback_query argument=<callback_data>;
  2. ждёт ваш BMCHAT-BOT-REPLY и публикует его в чат.

Кнопки с "url" вместо "callback_data" рендерятся как обычная гипертекстовая ссылка — BMChat откроет её в браузере, никакого callback не будет.

Аутентификация и безопасность

  • From на bot-апдейтах — это e-mail владельца BMChat. Привяжите вашу backend-логику только к этому адресу.
  • token_suffix внутри JSON — первые 16 символов вашего бот-токена. Используйте как «общий секрет».
  • Reply-маршрут жёсткий: BMChat принимает BMCHAT-BOT-REPLY только от того адреса, который указан в developer_email. Любой другой источник игнорируется.
  • Удаление бота или отключение переключателя — мгновенно прекращает доставку апдейтов. Полный аналог «Revoke token» у BotFather.

Пример: Python (IMAP + SMTP)

import email, imaplib, smtplib, json, re, ssl
from email.message import EmailMessage

ACC = "developer@example.com"
PWD = "<app password>"
TOKEN_PREFIX = "f8d2a1b0c4e5..."

def serve():
    imap = imaplib.IMAP4_SSL("imap.example.com")
    imap.login(ACC, PWD)
    imap.select("INBOX")
    while True:
        _, data = imap.search(None, '(UNSEEN SUBJECT "BMCHAT-BOT-UPDATE")')
        for num in data[0].split():
            _, msg_data = imap.fetch(num, "(RFC822)")
            msg = email.message_from_bytes(msg_data[0][1])
            handle(msg)
            imap.store(num, "+FLAGS", "\\Seen")
        imap.idle()  # use IDLE in production

def handle(msg):
    body = msg.get_payload(decode=True).decode("utf-8", "replace")
    header, _, payload = body.partition("\n---\n")
    update = json.loads(payload)
    if not update.get("bmchat", {}).get("token_suffix", "").startswith(TOKEN_PREFIX):
        return  # spoof attempt

    sender_owner = msg["From"]  # BMChat owner
    chat_id   = update["message"]["chat"]["id"]
    msg_id    = update["message"]["message_id"]
    bot_slug  = update["bmchat"]["bot"]
    cmd       = update["bmchat"]["command"]
    arg       = update["bmchat"]["argument"]

    reply = {"text": f"Привет, {update['message']['from']['email']}!"}
    if cmd == "forecast":
        reply["text"] = f"Прогноз для {arg}: +7°C"

    out = EmailMessage()
    out["From"] = ACC
    out["To"]   = sender_owner
    subj = f"BMCHAT-BOT-REPLY v1 @{bot_slug} chat={chat_id} in_reply_to={msg_id}"
    out["Subject"] = subj
    out.set_content(subj + "\n---\n" + json.dumps(reply, ensure_ascii=False, indent=2))

    with smtplib.SMTP_SSL("smtp.example.com", 465, context=ssl.create_default_context()) as s:
        s.login(ACC, PWD)
        s.send_message(out)

Legacy HTTP webhook

До 2.49.49 BMChat поддерживал POST на HTTP-эндпоинт (заголовок X-BMChat-Bot-Token, тело — Telegram-shaped Update). Этот канал по-прежнему работает: если вы заполните поле HTTP webhook URL в редакторе, BMChat сделает POST параллельно с почтовой отправкой. Удобно для интеграций, где proxy/relay уже подняты.

Ограничения и отличия от Telegram

  • Задержка — это задержка вашей почты. SMTP+IMAP IDLE на обычных провайдерах укладывается в 5–15 секунд.
  • Файлы и медиа в ответе бота пока не поддерживаются — только текст и inline-кнопки. Будут добавлены в 2.49.5x.
  • Нет edit_message_text, delete_message: в почте нет понятия «изменить уже доставленное письмо».
  • Нет групповых ботов с правами администратора — бот разговаривает только в чатах, где сидит владелец.
  • Один пользователь BMChat может держать любое количество ботов; ограничений нет.
